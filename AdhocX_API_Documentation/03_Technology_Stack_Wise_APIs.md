### Middleware / cross-cutting (NestJS)

- Global `ValidationPipe` (whitelist + forbidNonWhitelisted), `HttpExceptionFilter`, `TransformInterceptor` (`{data}` envelope), `TenantContextInterceptor` — wired in `apps/api/src/main.ts`.
- Guards: `JwtAuthGuard`, `RolesGuard`, `CorporateAccessGuard` (`apps/api/src/common/`), applied at class or method level per controller.
- Interceptors/pipes for uploads: `FileInterceptor` (multer) on document/logo/photo endpoints.
- SSE: `@Sse()` handlers in `CorporateTrackingController`, `NotificationsController`, plus manual `text/event-stream` in `CorporateRoutingController` streaming endpoints; auth via single-use `?ticket=` from `live-stream-tickets` / Redis stream tickets.

## 2. Express.js

**No standalone Express application exists.** Express is present only as NestJS's underlying HTTP adapter (`@nestjs/platform-express`) — all Express-level routing is generated by NestJS decorators. `apps/api/src/main.ts` configures Express-specific bits (body parser limits, CORS, prefix exclusion for uploads/docs).

---

## 3. Next.js

**Zero API routes / route handlers.** Verified: no `route.ts`/`route.js` files exist under `apps/admin`, `apps/ops`, `apps/corporate` (outside `node_modules`). All three portals are client-only Next.js 14 App Router apps that call the NestJS API via `src/lib/api/client.ts` fetch wrappers. Middleware (`middleware.ts`) performs client-side route protection only, not API handling.
